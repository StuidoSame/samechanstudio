# 자율 작업 절차

## Inspect → Plan

시작 HEAD와 사용자 변경, 실제 실행 환경을 기록한다. [GIT_POLICY](GIT_POLICY.md)에 따라 안전하게 동기화한다. Graft로 관련 경계를 좁힌 뒤 원본과 기존 테스트를 확인한다. 실행 가능한 완료 조건과 이번 작업에서 변경할 범위를 짧게 정한다.

## Implement → Verify → Repair

기존 아키텍처와 저장 데이터를 보존하며 최소 변경을 구현한다. 일반적인 구현 선택과 되돌릴 수 있는 로컬 수정은 자율 진행한다. 검증은 [TESTING](TESTING.md)에 따라 필요한 것부터 실행한다. 오류가 나면 종료 코드·관련 로그를 확보하고 원인을 분리한 뒤 수정한 범위만 재검증한다. 같은 원인에 새 증거가 없으면 재시도를 멈추고 차단 원인을 기록한다.

전체 테스트나 빌드를 관성적으로 반복하지 않는다. 기능 변경·실제 실패·미해결 위험이 있을 때만 검증 범위를 넓힌다. 개발 서버는 중복 실행하지 않으며 불필요한 watcher, Docker, 에뮬레이터를 띄우지 않는다.

## Commit → Report

변경 내용을 검토하고 독립된 검증 단위별로 로컬 커밋한다. 실제 변경만 커밋하며 설치·서버 실행에 파일 변경이 없으면 커밋하지 않는다. 완료 보고에는 결과, 검증 증거, 커밋, 실행 중인 URL, 남은 제한을 포함한다. 다른 OS를 실행하지 않았다면 정적 검토와 실행 검증을 구분한다.

안전 중단 경계는 [SECURITY](SECURITY.md)에 있다. 안전 중단이 필요한 부분 외의 독립된 작업은 계속한다. 보고서만 남기고 실행 가능한 환경 구축을 생략하지 않는다.
