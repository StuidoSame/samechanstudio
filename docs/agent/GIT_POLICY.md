# Git 정책

## 시작 상태와 동기화

`git status` → 원격이 있을 때 `git fetch` → 안전할 때 `git pull --no-rebase --ff-only` 순서다. 시작 브랜치와 HEAD를 기록한다. 네트워크·인증 실패 시 로컬 기준을 명시하고 안전한 작업을 계속한다. 분기된 이력은 자동 merge/rebase하지 않는다. 미커밋 변경이 있으면 pull을 강행하지 않는다.

새 브랜치가 필요하면 로컬 `codex/<purpose>`를 기본으로 사용한다. 환경 구축처럼 기존 브랜치에서 안전하게 수행 가능한 요청은 불필요한 브랜치를 만들지 않는다. 원격 브랜치 생성은 별도 명시적 요청이 필요하다.

## 초미세 로컬 커밋

- 한 독립적이고 검증 가능한 변경을 한 커밋으로 만든다. 문서도 내용 단위로 분리하되 커밋 수를 위해 무의미한 변경을 만들지 않는다.
- 타입은 `feat`, `fix`, `add`, `debug`, `chore`, `rm`을 사용한다. 예: `fix: make development scripts portable`.
- 명시적 파일 경로로 stage하고 staged diff와 관련 검사 결과를 확인한다. `git add .`로 사용자 변경·생성물·비밀정보를 섞지 않는다.
- 실패하거나 생략한 검증을 성공으로 기록하지 않는다. 훅을 우회하거나 Git 사용자·서명 설정을 임의 변경하지 않는다.
- 의존성 설치 시 lockfile diff를 별도 검토한다. 무관한 재해석이나 버전 갱신은 커밋하지 않는다.

## 금지

사용자 변경의 자동 stash/reset/clean/강제 checkout, 이력 강제 재작성, 승인 없는 push·force push·태그·운영 배포를 금지한다. 파일 권한을 수정하거나 대량 삭제로 오류를 회피하지 않는다. 샌드박스의 `.git` 쓰기 제한은 승인된 Git 명령의 실행 경계를 사용하고 설정 자체를 바꾸지 않는다.
